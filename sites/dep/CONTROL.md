# Пилот контроля файлов: `abhaz_test`

Режим включён в рабочей копии только в `projects/abhaz.env` для `abhaz_test` (`test`). Это обновление **не устанавливалось на хостинг**. Другие конфиги и `deploy_remote.sh` не менялись. Без флага сервер использует прежний путь выкладки, в том числе его прежние ограничения (см. `audit.md`). Не использовать старый обработчик или отдельный скрипт вручную для записи в защищённую цель.

## Установка обновления

Архив обновления **не содержит** рабочих `.env`, паролей, токенов, лога и данных сайта. Распаковать файлы `index.php`, `ajax.php`, `accet/js/app.js`, `accet/css/style.css`, `control/api.php`, `control/worker.py`, `control/directory_status.py` поверх файлов **одной версии** панели. Вне рабочей копии добавить в существующий `projects/abhaz.env` следующий блок, не заменяя остальное содержимое:

```ini
FTP_CONTROL_TARGETS=abhaz_test
GIT_COMMIT_NAME=fromserver
GIT_COMMIT_EMAIL=from@server.ru
FTP_NEW_FILES=
FTP_WRITE_BRANCHES=test,test/*
```

`FTP_WRITE_BRANCHES` — разрешения на изменение веток **в remote**, не список отображаемых веток. По умолчанию пилот не отправляет изменения в `main` или произвольную ветку. Выбрать существующую тестовую ветку или явно указать её настоящее имя; не ослаблять защиту веток GitHub. Служебные ветки `ftp-snapshots/…` должны быть доступны для создания и чтения. Без необходимости push чистый деплой допускается и из ветки только для чтения.

`FTP_NEW_FILES` — разрешённые маски *новых* файлов относительно корня сайта через запятую, например `src/*.php,assets/*.css`. Сначала пусто: изменения и удаления уже отслеживаемых файлов учитываются, а неизвестный новый файл показывается как «БЛОК». Добавлять маски только после проверки состава каталога. Не задавать `*`. Политика исключает распространённые файлы секретов и runtime-каталоги, но не распознаёт секреты по содержимому. Игнорируемые Git новые файлы не включаются. Если репозиторий **отслеживает** защищённый путь (например, `uploads/`, `.env` или `vendor/`), пилот откажется его публиковать, а не заменит молча.

## Перед первым запуском

1. Заменить опубликованные ранее секреты. Сделать резервную копию сайта и проверить её восстановление. Убедиться, что каталог из конфига — именно место записи FTP и что ни одна другая панель, цель, CI или cron не публикует туда параллельно. Выключить автодеплой внешнего CI при служебных push.
2. На стороне панели: PHP 7.4+ с `proc_open` и OpenSSH; под пользователем веб-процесса настроить SSH-ключ и заранее проверить и закрепить ключ хоста в `known_hosts`. Новый путь специально **не использует пароль из архива**, не выключает проверку ключа хоста и не использует `plink.exe`.
3. На стороне сайта: Linux, Python 3.9+, Git, доступ SSH-пользователя к файлам сайта, приватный домашний каталог вне web-root и свободное место для Git-объектов и временной выкладки. Настроить Git-доступ к `REPO_URL` **на этом хосте**, для этого пользователя (например, защищённым credential helper). Токен из PHP-конфига по SSH не передаётся. Коммиты подписываются указанными *именем и email*, не криптографическим ключом.
4. Договориться об окне обслуживания: на время синхронизации и выкладки остановить запись FTP, cron и редакторов, дождаться окончания уже открытых передач. Кнопка подтверждения — подтверждение оператора, а не механизм отключения FTP. Для PROD этот вариант публикации закрыт сервером.

## Работа оператора

- **Привязать к Git.** Для непустой папки без Git указать базовый SHA или подтвердить вершину ветки, проверить предварительный список. Отсутствующие файлы требуют отдельного подтверждения. Привязка не меняет сайт и ничего не отправляет в remote. Для пустой папки первая выкладка заполняет каталог, не создавая коммита удаления. Рабочая копия с подходящим `origin` распознаётся автоматически; зелёная кнопка «Привязано к Git» отключена. На первом действии проверяется, что её `HEAD` доступен в истории remote. Для каталога без `.git` все метаданные остаются снаружи.
- **Контроль.** `A/M/D` — добавлен, изменён, удалён. Контроль не меняет файлы сайта или remote. Содержимое файлов в журнал не выводится. Поддерживаются обычные файлы до 32 МиБ при чтении рабочей копии. Пилот сравнивает байты и признак исполнения, не воспроизводит сборку, LFS/smudge-фильтры и преобразования окончаний строк. Ссылки, submodules и нестандартные структуры требуют отдельной проверки. Использовать для целей, где сайт соответствует обычному файловому дереву Git.
- **Синхронизация.** Дельта сохраняется в служебной ветке; merge выполняется **вне** сайта, push — без force. Конфликт показывает имена файлов и ветку снимка. Объединить её с выбранной веткой обычным merge (не squash), разрешить конфликт и повторить. Синхронизация сама не выкладывает ветку на FTP.
- **Деплой.** Та же проверка и синхронизация, затем запись проверенной ревизии. У существующего клона после публикации `HEAD` указывает непосредственно на выложенный коммит (detached HEAD). В чистой папке не создаётся публичная `.git`. Повтор без внешних изменений не создаёт новых коммитов. При одновременном запуске для одной цели второй запрос получает «Цель занята».

## После сбоя

Закрытая служебная папка на хосте: `~/.dep-control/<ключ-цели>/`, где ключ — первые 24 символа SHA-256 абсолютного пути. `state.json` — последняя подтверждённая база и снимок; `operations.jsonl` и `runs/` — локальные записи операций, не общий веб-лог. Служебные ветки и записи автоматически не удаляются: следить за местом, не удалять снимок до разрешения конфликта. Изменение флага в конфиге не откатывает сайт; не выключать флаг для обхода ошибки.

Публикация на TEST обновляет файлы по одному (через временный файл и замену); **это не атомарное переключение всего сайта**. Перед первой записью создаётся `incomplete.json` с исходным состоянием и ожидаемым SHA. При обрыве он блокирует дальнейшую привязку, синхронизацию и деплой, чтобы панель не приняла собственную незавершённую выкладку за FTP-правки.

Если появился этот маркер: оставить внешнюю запись остановленной; проверить, что SSH-процесс завершился; снять копию текущих файлов и служебного состояния. Сопоставить `desired`, исходный снимок, фактические файлы и `HEAD` клона. Восстановить согласованную версию **из проверенной копии** либо завершить публикацию указанного SHA вручную, сохранив отдельные пользовательские файлы. Проверить файлы, `HEAD` и соответствие `state.json` восстановленной базе. Только после сверки ответственный администратор снимает маркер. При неизвестном состоянии не удалять маркер и не нажимать «Деплой ещё раз». Ошибка SSH может означать потерю ответа, а не отсутствие push — проверить remote и журналы.

## Проверка сборки

`python3 -m unittest discover -v -s tests` из корня проекта (Python 3.9+, Git, PHP CLI в PATH). Тесты используют временные каталоги и локальный bare-репозиторий. Для PHP-маршрута SSH заменён локальной заглушкой транспорта: тесты не используют конфиги хостинга. Статическая проверка: `php -l` для изменённых PHP-файлов, `node --check accet/js/app.js`. Доступы реального хостинга, FTP-блокировка, права файлов веб-сервера и реальный SSH-канал проверяются владельцем отдельно на TEST.

## Ветки в карточках директорий

Под каждой доступной целью на странице проекта видна отдельная строка «Ветка». Список считывается одним запросом на хост проекта (OpenSSH, проверенный ключ хоста, вход по ключу, Python 3.9+, Git), без fetch и без изменения файлов. Это требование для индикатора, а не изменение старого сценария деплоя. При отсутствии доступа карточка остаётся доступной для выбора, но показывает «не удалось проверить».

В обычной рабочей копии источником служит локальная ветка HEAD; в защищённом режиме имя сохраняется вместе с SHA только после проверки опубликованных файлов. Сама привязка или синхронизация ветку на карточке не подменяет. Пустая цель — «нет»; detached HEAD или старое состояние без подтверждённого имени — «не определена». Следующий успешный защищённый деплой сохранит недостающее имя. Маркер незавершённой выкладки отображается отдельно. Сведения обновляются при открытии страницы, возвращении на вкладку, после попытки деплоя, раз в минуту на видимой странице и вручную кнопкой «Обновить ветки». Скрытые правами директории не запрашиваются.
