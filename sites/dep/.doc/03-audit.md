# 03. Актуальный аудит: проблемы и решения

Аудит сопоставляет текущий код и наблюдавшиеся журналы. Офлайн-тесты проверяют логику на локальных репозиториях, но не подтверждают права токена, правила GitHub, производительность и настройки веб-сервера реального хостинга.

## Исправлено

| Наблюдение | Причина | Что сделано |
|---|---|---|
| Новый `123123` пытались отправить и получали `403`, хотя деплой не затрагивал файл | Старый снимок включал новые неигнорируемые файлы | Снимок ограничен управляемыми путями; посторонний файл остаётся на месте |
| Сотни процентов Git скрывали итог | Git писал каждое промежуточное состояние загрузки | Итог отдельным цветным блоком; промежуточные дубли отфильтрованы |
| При запуске терминал молчал | Первая строка зависела от серверного ответа | Старт и таймер отображаются сразу на клиенте; далее показываются реальные серверные этапы |
| Выбор другой ветки блокировал интерфейс | Клик автоматически запускал тяжёлый контроль | Контроль запускается вручную |
| Повторно скачивалась история выбранной ветки | Контроль использовал пустой репозиторий | Постоянный кэш веток, инкрементальный fetch |
| Контроль читал дерево всего сайта и писал Git-объекты | Общий тяжёлый алгоритм снимка | Контроль читает объединение нужных путей, без записи объектов; проверка путей и хеширование пакетные |
| Деплой того же чистого коммита занял 106,9 с | Предпросмотр, подтверждение, повторные проверки ничего не меняли | Один проход и быстрый выход без push, записи или подтверждения |
| Другой SHA с теми же файлами запускал полный деплой | Сравнение учитывало только равенство SHA | При чистом совпадающем дереве обновляются только метаданные после подтверждения |
| Предпросмотр мог получить ошибку занятой записи | Блокировка бралась раньше подтверждения | Предпросмотр не держит блокировку записи; подтверждённые записи сериализуются |
| Целевая ветка обновлялась до проверки итоговых путей | Слияние сразу сопровождалось push | Для обычного защищённого деплоя проверки перед push; при конфликте отдельно сохраняется только снимок |
| Итоговое время включало паузу оператора, а время ответа могло опережать отправку | Разные часы и один таймер | Для пользовательской операции разделены предпросмотр, ожидание и исполнение; отметки отправки/ответа используют часы браузера |

Прошлые замеры около 95 с и 60 с относились к разным версиям и сценариям. Пакетную проверку путей замеряли в песочнице на синтетических файлах; это не замер всей операции. Новый алгоритм нужно сравнивать на одинаковой цели и одинаковом SHA.

## Открытые риски и решения

| Приоритет | Риск | Рекомендуемое действие |
|---|---|---|
| До реального запуска | Токен способен читать ветки, но GitHub вернул `403` при push | Проверить право записи, разрешение создания служебных веток и правила целевой ветки. Сначала испытать на тестовой ветке |
| Высокий | Предпросмотр и выполнение используют разные веб-запросы; снимок пересобирается. При большой выкладке остаются повторные обходы | Хранить неизменяемый снимок с ID, проверять актуальность перед записью и не пересобирать согласованный снимок без нужды |
| Высокий на больших каталогах | Нет фоновой очереди; SSH имеет предел около 180 с, браузер — 195 с, прокси может завершить запрос раньше | Вынести тяжёлые операции в устойчивый обработчик с сохранёнными статусами, прогрессом и восстановлением после разрыва |
| Высокий при внешней записи | Сканирование и выкладка не образуют атомарный снимок; после сверки остаётся окно гонки | Остановить FTP, cron и другие записи в окно обслуживания; иметь проверенную резервную копию. При необходимости позже хранить релизы отдельно и переключать публикацию целиком |
| Высокий при публикации | Широкий токен доступен доверенному SSH-хосту во время операции; исходный архив и конфиги могут содержать секреты | Никаких публичных архивов с конфигами; при экспозиции заменить секреты. Минимизировать область токена. Для масштабирования рассмотреть репозиторно ограниченные токены GitHub App |
| Средний | Список блокируемых имён не является сканером секретов; секрет возможен в обычном отслеживаемом файле | Не хранить секреты в отслеживаемых файлах; добавить секрет-сканирование при распространении режима |
| Средний | Git и файловая выкладка не одна транзакция. После успешного push возможен отказ записи сайта | Сверять Git и сайт отдельно. Будущему фоновому обработчику сохранять факт подтверждённого push и SHA на каждом этапе |
| Средний | Служебные ветки и кэш могут расти; не все хостинги одинаково обслуживают Git-объекты | Определить квоты, срок хранения снимков и правила обслуживания после успешной выкладки, не удалять активную базу |

## Что покрывают проверки

`bash tests/run.sh` проверяет ACL и CSRF, PROD-изоляцию, обычную выкладку, SSH/маскирование, привязку, выбранную ветку, коллизии, конфликт, сохранность неуправляемых файлов, удаление управляемых, повторную выкладку, одинаковое дерево с новым SHA, подпись и устаревание подтверждения, параллельные чтения и маркер прерванной выкладки. Не заменяет тест в браузере на боевом прокси и проверку с реальными правилами GitHub.
