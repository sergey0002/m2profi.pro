# 05. Сохранение снимка между предпросмотром и подтверждением

**Статус: проект доработки, не реализовано.** Сейчас предпросмотр и подтверждение — отдельные HTTP-запросы; подтверждённая операция пересобирает снимок.

1. При предпросмотре сформировать дерево управляемых файлов и сохранить его на хостинге вне `www`. Привязать снимок к ID, действию, проекту, цели, оператору, ветке, вершине ветки, базе выкладки и предыдущему снимку. Зафиксировать срок действия и удерживать Git-объекты от сборки мусора.
2. Вернуть панели ID подтверждения и список файлов. До «Да» не отправлять ничего в GitHub и не менять сайт.
3. После «Да» проверить права и подтверждение, взять блокировку записи и сверить Git-состояние. Использовать сохранённое дерево для подготовки слияния, а не собирать новый снимок. Переиспользовать защитную сверку перед push и записью для проверки актуальности сайта. При изменении дерева, ветки или появлении коллизии остановиться и запросить новый предпросмотр.
4. Сделать подтверждение одноразовым и различать отмену, истечение срока и уже начатое выполнение. По истечении срока очищать только неактивные снимки; при обрыве не повторять push вслепую.

Ожидаемый результат для обычного защищённого деплоя: подготовка снимка, одна защитная сверка перед записью и проверка результата вместо повторной сборки после подтверждения. Это не устраняет гонку с внешней записью и не решает веб-таймауты само по себе. Фоновая очередь — отдельный этап.
